# 判题沙箱 Docker 化迁移指南

## 1. 架构

```
浏览器 ── HTTPS ──> server.py (Windows, 继续跑 HTTP/认证/题库/会话)
                        │
                        │ JUDGE_BACKEND=docker (默认)
                        ▼
                docker run --rm --network none --cap-drop ALL ...   (每测试用例一个容器)
                        │
                        ▼
         aijudge-judge:latest (Debian + g++, 非 root, 只读根文件系统, tmpfs)
                  编译 main.cpp -> 运行 -> stdout/stderr/退出码
```

- 判题从"本机直接执行"改为"一次性 Linux 容器内编译+运行"。
- 容器无网络、非 root、只读根文件系统、剥离全部 capabilities、默认 seccomp、
  内存 512MB / CPU 1 核 / 进程数 64 上限, 运行完即销毁。
- Docker 不可用/失联时 **fail-closed 拒绝判题**, 绝不回退到本机执行。
- 输出结构与原 judge.py 完全一致, server.py API 与前端零改动。

## 2. 部署前提 (Windows CVM 上安装 Docker)

推荐方案 A (改动最小): 同一台 Windows 服务器装 Docker Desktop (WSL2 后端)。
推荐方案 B (最稳): 整体迁到 Linux CVM (腾讯云轻量应用服务器即可), server.py
是纯标准库, 直接 `python code/server.py` 运行; 证书/题库/数据目录原样拷贝。

### 方案 A 步骤 (Windows + Docker Desktop)
1. 确认 CPU 虚拟化可用: `systeminfo` 中 "Hyper-V 要求" 全部为"已检测到"。
2. 启用 WSL2:
   ```powershell
   wsl --install
   wsl --set-default-version 2
   ```
   装好后重启; 若云主机无嵌套虚拟化, 方案 A 不可行, 改用方案 B。
3. 安装 Docker Desktop (勾选 "Use WSL 2 based engine"), 登录后在
   Settings -> General 勾选 "Start Docker Desktop when you sign in",
   并确认 WSL Integration 开启。
4. 验证: `docker version` 能显示 Client/Server 且 Server 为 linux。

### 方案 B 步骤 (Linux CVM)
```bash
# Ubuntu 22.04/24.04
curl -fsSL https://get.docker.com | sh
systemctl enable --now docker
```
把 `project/` 目录拷到 Linux 服务器 (排除 runtime.zip, 用系统 g++ 或容器内编译),
`pip` 无需依赖, 直接运行即可。

## 4. 配置与启动

server.py 新增环境变量:

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `JUDGE_BACKEND` | `docker` | `docker`=容器沙箱(推荐); `local`=本机执行(仅限可信内网/开发, 不安全) |
| `JUDGE_IMAGE` | `aijudge-judge:latest` | 判题镜像名 |
| `JUDGE_TIMEOUT` | `5` | 容器内运行超时(秒) |
| `JUDGE_CONTAINER_TIMEOUT` | `40` | docker run 整体超时(秒, 含编译) |
| `JUDGE_MAX_CONCURRENCY` | `2` | 并发容器数上限 |

在 `start.ps1` 启动服务前设置:
```powershell
$env:JUDGE_BACKEND = "docker"
$env:JUDGE_IMAGE = "aijudge-judge:latest"
# 启动前等待 Docker 就绪
$n = 0
while (-not (docker info *> $null) -and $n -lt 30) { Start-Sleep 1; $n++ }
if (-not (docker info *> $null)) { Write-Error "Docker 未就绪, 拒绝启动(判题将不可用)" }
```

## 5. 上线后验证清单 (必须逐项复测)

用测试账号提交以下代码, 期望全部被容器拦截 (不再能读到主机文件/执行命令):

1. 读文件 (旧漏洞 PoC, 期望输出非 passwd 内容或权限错误):
   ```cpp
   #include <stdio.h>
   int main(){ FILE* f=fo\
   pen("C:\\Windows\\win.ini","r"); if(!f){puts("BLOCKED");return 0;} char b[100]; fread(b,1,99,f); fwrite(b,1,99,stdout); }
   ```
   期望: 容器内无 `C:\Windows\win.ini`, fopen 失败 → BLOCKED (文件系统隔离生效)。
2. 命令执行 (`sys\<换行>tem` + 运行时构造 "dir C:\\"): 期望容器内无 cmd / C:\,
   命令失败, 无敏感输出 (Windows 命令在 Linux 容器内不存在)。
3. 读取容器内 /etc/passwd: 容器非 root 且无网络, 读取成功也只是容器自身文件,
   主机文件不可达。
4. 死循环: 期望 ~5s 判 timeout (容器内 timeout + docker stop-timeout 双保险)。
5. 大内存 400MB: 期望分配失败 (容器 512MB 含编译, 运行进程受限)。
6. 正常 A+B 提交: 期望 3/3 passed (回归)。
7. 停掉 Docker Desktop 后提交: 期望返回"判题沙箱不可用" fail-closed 提示, 而非本机执行。

## 6. 兼容性注意事项 (MinGW -> Linux g++)

- `long` 在 Windows 是 4 字节, Linux x64 是 8 字节; 依赖 32 位 long 的解法行为可能变化
  (本题库题目均为 int 级运算, 无影响)。
- 输出编码: Linux 容器输出 UTF-8, 与 server 端 expected 一致; 顺带修复了旧版 GBK 乱码。
- `#include <bits/stdc++.h>`、`-std=c++17 -O2` 均可用; `windows.h` 类代码本就被黑名单拦截。
- 判题结果 API 结构不变, 前端无需改动。

```powershell
# 恢复 server.py
Copy-Item project\code\server.py.bak project\code\server.py -Force
# 删除新增文件 (可选)

# 重启服务后即回到旧判题路径 (JUDGE_BACKEND 未设置时也默认走 docker, 回滚后旧代码无此逻辑)
```
